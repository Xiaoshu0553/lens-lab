# 研究设计与记录说明

本文说明当前系统实现与数据解释边界，不替代预注册、伦理审查、问卷验证或正式统计分析方案。

## 研究范围

课题关注生成式人工智能的信息公平性与自适应干预。当前软件以信息素养、年龄情境和主动澄清为切入点，实验条件是标准交互与主动澄清交互。规范表达、口语表达等表达风格不是当前实验因素，现有分组不能直接解释成语言表达差异的因果检验。

参与者填写年龄区间、教育阶段和对核查通知／规则的熟悉程度，完成前测后进入资料查证任务。年龄区间并非常识储备的直接测量，教育阶段和熟悉程度是额外控制变量。

## 问卷与年龄任务

系统有 9 个年龄区间：12–14、15–17、18–24、25–34、35–44、45–54、55–64、65–74、75 岁及以上。每份问卷 30 题，其中 18 道为共同候选锚题，12 道为年龄情境题；9 卷共 270 个题位、126 种独立材料。

问卷采用短句、分行材料和具体对象，先说明要判断的问题，再给出必要信息。最后一项“我暂时不会选”区分个人不确定与正确结论“资料还不足以判断”。题目难度尚未标定，不预设易中难各 10 题。实际阅读负担、难度与适配范围需通过试做验证。

9 套年龄任务分别使用虚构活动报名场景，每套有 4 种私事实情境。公共规则、资料预算和选项文字在 4 个情境间相同；参与者掌握的两个个案事实会改变最优方案。历史大学资助任务及旧记录仍可保留，但不作为当前所有成年参与者的共同背景。

问卷版本、任务、评分与案例事实保存为会话快照。修改材料不应回写历史作答，旧版与新版应分别分析。共同题并不自动证明量尺等值，不同年龄的问卷百分数和任务分数在校准前不宜直接合并比较。

## 分配与交互

系统在年龄区间、信息素养得分区间和当前任务等条件内平衡分配案例情境与标准组／澄清组。当前统计还约束问卷、设计、模型配置、运行模式、澄清策略和对应提示词版本，避免将不同方案混成同一批结果。

`module` 策略使用独立判断模块处理澄清，`prompt` 策略使用提示词路由；`demo` 固定使用模块策略。澄清针对会改变当前结论的缺失个案事实，已经明确提供的情况不应重复追问，也不应因为口语或短句本身触发追问。

资料查询与个案事实补充分别处理。模型可以参与选择资料卡和判断路由，但资料正文来自冻结任务库，并按主题、时效和适用范围校验。资料不支持所问事项时应说明未覆盖，每轮显示一项资料。直接索要最终答案时，系统引导参与者核查具体条件。

完成两轮有效回复后可进入决策阶段；对话达到上限时也允许结束信息收集。进入决策后不能继续提问。默认上限为 12 轮、30 分钟，由 `MAX_TURNS` 与 `MAX_MINUTES` 控制，正式收集期间应保持配置不变。

## 最终选择与评分

参与者分别从 5 个参加方案和 5 个办理方案中各选一项。参加方案最高 80 分，办理方案最高 20 分，合计为 0–100 的决策质量分。两组选项独立随机排列，公开选项标识不透露内部得分。

评分依据会话开始时冻结的选项与情境，首次成功提交后不再修改选择、分数或结束时间；不使用人工审核改写客观得分。错误选项允许同分，不强求五档严格递增。平台另存方案是否可办理和是否最优，这些指标与决策质量分不同，分数不等同于成功率。

这些评分属于待验证的研究设计，仍须检查内容合理性、任务难度、情境等值和测量误差。

## 时间与过程计数

| 字段 | 定义与限制 |
| --- | --- |
| `task_completion_seconds` | 前测完成后创建任务会话，到首次成功接受最终提交的经过秒数 |
| `dialogue_elapsed_seconds` | 创建会话到进入决策的经过秒数 |
| `decision_elapsed_seconds` | 进入决策到提交的经过秒数 |
| `pretest_time_seconds` | 当前没有记录问卷答题起点，保持空值，不补造时点 |
| `ai_clarification_count` | 已保存 AI 消息中主动澄清动作的次数 |
| `ai_guidance_count` | 已保存 AI 消息中任务引导动作的次数 |
| `ai_prompt_count` | 主动澄清与任务引导次数之和，按消息动作复算 |

任务时间包括阅读、AI 回复等待、中途停留和提交前反馈，不是活跃页面操作时间。刷新并恢复同一会话不重新计时，缺少必要时点时保持空值。原始时点使用带时区的 UTC，后台显示北京时间。回复服务耗时包含规则答复处理，不能当作纯模型推理耗时或模型调用次数。

一般资料回复、问候、事实确认与资料未覆盖回复不计入 AI 提示次数。过程提醒只说明观察到的作答或交互特征，不决定提示次数，不自动排除样本，也不证明参与者答题无效。没有对应平台起点的模拟前测时长不应用于过程判断。

## 导出与纳入

所有导出均需管理员认证。

| 接口 | 内容 |
| --- | --- |
| `/api/admin/export?kind=raw&format=csv` | 常用原始记录导出，保留全部记录 |
| `/api/admin/export?kind=analysis&format=json` | 当前版本中问卷完整且客观题已提交的记录 |
| `/api/admin/dialogue-export?format=json` | 与完成记录使用同一连接编号的有序对话 |
| `/api/admin/archive-export?kind=raw&format=json` | 内部完整归档，含真实会话 ID、来源、任务快照、事件及审核历史 |

`kind` 可用 `raw`／`analysis`，`format` 可用 `csv`／`json`。常用记录导出使用 71 个固定列，按人口信息、实验条件、30 题答案、任务结果、过程与时间排列；CSV 使用中文表头，JSON 使用英文键。

常用页面和导出通过永久编号 `record_id` 连接，新记录追加编号，删除后不复用。独立对话 JSON 按会话保存有序消息，CSV 按消息逐行列出。内部完整 ID 与来源保留在受认证保护的归档中。

分析记录按当前研究版本、问卷完整和客观提交自动确定，不依赖人工审核状态。未提交记录没有最终分数与完成时长，JSON 为 `null`，CSV 留空。记录页仍保留历史记录，并提供是否属于当前分析范围及排除原因。当前所有记录均完成且属于同一方案时，原始导出和完成导出的人数可以相同。

图表中的人数实际是会话记录数。系统没有参与者身份去重机制，同一人重复开始可能产生多条记录；不能把会话数直接宣称为独立参与者人数。

## 研究者试跑与合成展示

`/admin/preview` 使用独立浏览器存储，记录为 `record_kind=researcher_preview`，不占普通参与者分配名额，不进入普通逐题分析或常规研究导出。普通参与者记录为 `participant`，无法确认来源的旧记录可保留为 `unclassified`，不应自动改为参与者记录。

`demo` 为规则演示，`pilot` 为真实模型预测试，两者均不能与 `live` 正式数据混算。`pilot` 记录中保留的 `is_demo` 标记是材料／阶段标记，不意味着没有调用真实模型，判断运行模式应同时查看 `run_mode`。

隔离合成展示使用 `SHOWCASE_MODE=1`、`demo` 模式和独立 `showcase.sqlite3` 数据库。启动保护在初始化前检查身份。导入流程依赖单独批准并校验的来源包，本仓库没有附带该包，也不会在普通启动中自动生成样本。历史合成包的目标均值、抽样清单和模拟时点属于演示设计，不能作为实证发现；模拟对话不代表真实模型生成，也不应伪造模型回复耗时。

## 逐题分析与组间比较

后台提供答对率与 95% Wilson 区间、不确定率、题余分相关、高低组区分差、干扰项选择率及 KR20。小样本、同分重叠和零方差需要单独解释；无数据时不宣称题目区分度高，不按后续任务成绩筛选前测作答，也不自动删题。

任务组间比较先在各情境内比较，再按固定等权汇总；任一情境缺组时不填造结果。分差是不同会话之间的组均值差，不是同一人的前后提高率。正式推断可在预先确定的模型中检验连续素养与澄清条件交互，并控制案例情境；不预设澄清必然有效或必然缩小差距。

公开结果前仍需认知访谈、逐题审查、差异项检查、跨年龄与跨情境等值检验，并处理重复参与、缺失、退出、样本量和多重比较等问题。

## 参与者保护与运行边界

页面不要求姓名、学号或电话，参与者可以退出并请求删除当前会话。对话仍可能包含主动输入的个人信息，部署者需要提供数据处理说明、控制访问、制定留存及删除方案。远程模型服务会收到对话，研究者应在同意流程中说明具体服务与处理范围。

`pilot`／`live` 的未成年人入口有邀请码和专门说明门槛，但技术门槛不能独立验证监护人身份，也不能替代真实同意流程。

管理员网页登录使用有期限的 HttpOnly Cookie，脚本可使用 Basic 认证。生产部署须使用 HTTPS 并设置随机凭证。默认单进程 SQLite 适合本地运行和小规模预测试，大规模收集前需验证并发、备份、恢复和访问控制。软件通过测试不等于研究已具备有效性、伦理许可或正式招募条件。
