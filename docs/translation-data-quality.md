# 翻译数据、会话计数与评审证据

本页说明后台统计与评审的实际含义。原问卷、对话、时间和译文均保留；审计或新增评分不会将记录改写成另一种来源，也不会重写历史译文。

## 计数与时间

- 后台的“翻译会话数”按会话编号计数。同一使用者可有多次会话，不能据此推导独立使用者人数。
- “已提交译文”是完成首次提交并冻结的会话数；逐字相同的译文仍分别保留，不静默去重。
- “翻译会话时长”由会话创建至最终提交的实际 UTC 时间差计算，不包含会话创建前的问卷作答。模型等待、停顿和真实执行的脚本等待都在这段时间内。
- 客观问卷含18题，按候选阈值分组；6题实践自评单独保存。候选问卷不构成已验证的翻译能力测量工具。
- `record_kind=participant` 表示进入参与流程的记录类型；`data_purpose` 表示部署用途。两者都不能单独证明记录由真人独立完成。来源应由原生成清单或明确的操作人员证据核验，保留在技术审计字段。

## 已有批次的只读检查

2026-10-30 下载的 v3 归档快照包含24份已提交译文及1份早期研究者试跑。24份译文为125—130个 Unicode 字符，共21种逐字不同的全文，存在3组双份重复。24份共60轮模型回复，保存的 API 事件与轮次一致；每份提交都等于其最后一次模型回复起止标记内的原文。该归档不能说明之后新增会话的来源或内容。

当时24份会话均使用同一短原文、相同翻译委托、`deepseek-flash`、温度0和共同的最终请求。首轮 S 回复本身也为125—130字符，7/12份最终译文与首轮相同。生成器只提取模型原文并移除标记和首尾空白，没有将文本裁剪至125—130字符或替换成固定译文。重复、高相似度或相近长度本身不能证明伪造，也不能证明译文质量相当。

生成器中的问卷与使用者消息由预设场景产生，并根据预设能力层改变背景分享策略；它不等于真实学生分布。其记录可用于检查平台及模型调用流程，不能据此验证真实翻译使用者的能力差异或公平性效应。后续改进应预先设计行为场景或采集真实参与过程，不以目标长度、重复率、预期分差来筛选或改写译文。

受管理员认证保护的 `/api/admin/translation/data-audit` 和完整记录详情接口单独提供聚合核验与技术证据，不属于下方六项标准业务数据下载，也不改写记录。完整记录接口中的 `active_assessment` 返回当前批次结果；即使配置从5次改为7次再回到5次，原5次批次结果仍可核对复用，避免重复调用。

本地只读审计入口：

```sh
python scripts/audit_translation_data.py --help
```

工具默认只读。涉及来源证据标注时，先核对完整清单和请求映射；不要将来源不明的记录自动归为真人，不补造时间或行为。

## 六项业务数据下载

后台“数据导出”保留记录、对话、评分各一份 CSV 和 JSON，共六个下载入口。两种格式使用相同的业务字段白名单：

- 记录：记录编号与类型、能力总分和百分比及分项、客观问卷与自评答案、翻译会话时间、最终译文、质量总分和五维分项。记录文件不嵌套完整 `assessment` 对象。
- 对话：会话编号、记录类型、交互条件、说话方、消息正文及时间。
- 评分：记录类型、评审时间 `evaluated_at`、会话／模型标识、实际模型名、五维分数、总分、权重、极值处理、评分依据和严重错误。

下载范围不受后台表格筛选影响，保留全部记录及历次评分。此轮数据共26条记录，其中25条为 `participant` 翻译会话、1条为 `researcher_preview`；标准下载保留 `record_kind` 区分这些记录，不将研究者试跑计作普通翻译会话。历史评分以 `evaluated_at` 区分，原评分不覆盖。

翻译会话时长从提交问卷、创建翻译会话起计算，至首次最终译文提交结束；问卷作答时间不包含在该时长中。

六项标准下载不包含数据用途、技术来源、版本与快照、收集或评审批次标识、摘要哈希、API 原始响应及响应元数据。这些技术证据继续保存在数据库及受保护的完整记录／审计接口，按需要单独核对和归档。

## 两种评审方式

| 模式 | 实际调用 | 可以说明什么 |
| --- | --- | --- |
| `distinct_models` | 5—9个不同模型，各自获得相同材料与完整五维量规 | 模型间评分差异；模型的训练数据与偏差仍可能相关 |
| `repeated_sessions` | 复用已保存的对话模型 API，为每份译文建立5—9个全新上下文会话 | 同模型重复评分的波动；独立模型数仍为1 |

重复模式准确称为“同模型多会话重复评审”。上下文彼此分开不代表统计误差独立；它不能充当多个不同 AI，也不能保证共享偏差被抵消。温度较低时重复评分可能完全相同，应保留实际结果，不添加扰动。

每个模型或会话都评分全部五维：语义准确、语境与人物一致、中文流畅、文体与声音、完整与克制。共同维度权重为35/25/15/15/10。服务端先计算每次评分总分，去除一个最高和一个最低总分，再对保留结果按预设权重归一化汇总；各维度均分使用同一组保留结果。原始分、依据、极值处理及分歧都保留。正式解释仍需抽样人工盲评和一致性校准。

评审只获得共同原文、完整背景、量规及最终译文，不获得问卷能力、交互条件、翻译对话或其他评分。首次重复评审的各会话均使用全新上下文；失败重试可复用同一批次、相同译文与提示下已成功的评分，仅补调缺失会话。任一评分未完整通过时不发布部分综合分。

后台切换为重复模式时只需保存：

```json
{"evaluation_mode":"repeated_sessions","evaluation_repetitions":5}
```

服务端复用已有对话 API 凭据。`judges` 返回当前有效评审会话；`configured_judges` 保留原来的不同模型连接。切回不同模型模式时无需重新填写这些连接的已有密钥。

## 批次和重新评审

一个 `evaluation_batch_id` 对应明确的评审方式、有效模型或会话配置、评分提示及材料。统计均分只使用当前批次的完整评分；不同批次结果分开保留，不能混合均分。

评审请求可携带三个前置条件：

```json
{
  "evaluation_batch_id":"当前批次ID",
  "submission_sha256":"UTF-8译文的SHA-256",
  "allow_reassessment":false
}
```

服务端在事务内检查批次与译文摘要，不一致时返回409且不发出新模型请求。同批次已完成结果可直接返回；已有其他批次评分时，默认拒绝重评。明确启用 `allow_reassessment=true` 后，原结果进入历史批次，新的评分仍保存独立批次及完整依据。

后台“批量评审当前已提交译文”顺序处理当前 cohort 中已提交的翻译会话，核对每份译文摘要，并跳过已有同批次结果。默认保留其他批次评分；启用重评选项后才请求新批次评分。停止按钮停止后续会话，已被服务端接受的请求会继续完成。配置变化时停止后续付费调用。

## 可恢复的批量 CLI

先在本机或容器环境配置 `ADMIN_PASSWORD` 或 `TRANSLATION_EVALUATION_ADMIN_PASSWORD`。不要把密码放进命令、URL或清单。

`ids.json` 只包含明确选择的会话编号：

```json
["第一个会话编号","第二个会话编号"]
```

```sh
python scripts/evaluate_translation_records.py \
  --base-url http://127.0.0.1:8000 \
  --ids-file /app/data/evaluation/ids.json \
  --manifest /app/data/evaluation/run.json \
  --workers 1
```

可增加 `--cohort` 固定期望收集版本。已有不同批次评分需要明确增加 `--allow-reassessment` 并使用相应权限的清单。工具始终顺序处理会话；每份译文内部的多个评审会话由服务端执行。

清单以0600权限原子写入，保存明确 ID、收集版本、评审批次、每份译文摘要、请求次数及结果摘要，不保存密码或自行生成分数。同一清单恢复时核对这些不变项；更换批次须使用新清单。请求超时后先读取待处理状态，等待已接受任务完成，不直接重复发送。502最多重试两次，重试预算跨恢复保留；401、403及其他未知错误立即停止。配置或译文发生变化时保留进度并停止。

标准评分下载保留记录类型与评审时间，供业务分析并区分历次评审。需要核对完整批次、评分提示、原始 API 响应或技术来源时，使用受保护的完整记录／审计接口，与私有技术清单单独归档。文字重复、自动请求或实际模型调用都不应被改写为另一种参与来源。
