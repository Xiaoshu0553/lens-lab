# 翻译流程展示样本的生成方法

此脚本用于院赛的平台流程展示。问卷答案和参与者消息由脚本模拟，助手回复通过运行中的平台实际请求已配置的云模型；它们不是中国矿业大学真实受试者的实测结果。界面可在展示入口统一说明用途，技术来源保存在每条记录的 `data_purpose` 与私有批次 manifest 中，无须在表格每一行重复标注。

## 前置条件

- 平台采用 `pilot` 模式，`/api/translation/info` 明确返回 `data_purpose=demonstration`、`demonstration_mode=true`。
- 已部署矿大本科生入口：年龄 `18 / 19 / 20 / 21 / 22 / 23-plus`；年级 `year-1` 至 `year-5-plus`；学段固定为 `bachelor`。
- 管理端已配置具有密钥的 HTTPS 云模型。生成器拒绝规则演示、本地模型和研究用途实例。
- 执行环境提供 `ADMIN_PASSWORD` 与需要时的 `PARTICIPANT_ACCESS_CODE`；也支持 `TRANSLATION_SAMPLE_ADMIN_PASSWORD`、`TRANSLATION_SAMPLE_ACCESS_CODE` 覆盖。脚本不会打印凭据或将其写入 manifest。平台源码根目录的已有私有 `.env` 可由 `load_dotenv()` 读取。

## 执行

从部署的源码目录运行，以下仅为不含凭据的示例：

```sh
python scripts/generate_translation_samples.py \
  --base-url http://127.0.0.1:8004 \
  --count 24 \
  --seed 20261030 \
  --manifest /opt/lens_lab/translation-data/presentation-batch-20261030.json \
  --workers 4 \
  --pace-seconds 180
```

`--base-url` 必须是站点源地址，不接受 URL 中的凭据、查询参数或路径。远端站点必须使用 HTTPS；回环地址允许 HTTP。服务器内部端口只用于从本机访问相应实例，不能据此假定该端口已对外开放。

默认 `--workers 1`、`--pace-seconds 0`。启用等待时，每条会话按固定 seed 抽取 `0.7–1.8 × pace-seconds` 的总等待，将其均分到计划的 2–4 轮消息之前，以不超过 30 秒的小片段实际等待并保存进度。四个 worker 各自使用独立 HTTP 客户端；manifest 快照写入串行化，另一进程无法同时持有同一 manifest。等待不会修改服务器的开始时间、结束时间或模型回复耗时。

中断后，用相同的 origin、count、seed、pace 和 manifest 重跑。可以调整 worker 数量。脚本重用 start/message 请求编号；已确认完成的请求不会重发、不会再次等待，成功会话不会被重新建立。正在生成的请求先同步。过期会话不会通过伪造时间或新建替身会话“修复”；批次会保留完成部分并报告需要处理的样本。

`json-content-field-v2` 补丁明确要求模型将译文标记置于系统规定的 JSON `content` 字符串内，避免将“仅输出译文”误解为绕开 JSON 外壳。恢复旧批次时，已完成的旧 final 请求原样保留；尚未发送或服务端已记录失败、且无待生成请求的旧 final 轮次，可以改用稳定的 `message-N-json-format-retry` 新请求编号。原编号、原文与状态完整保留在 `format_retries`，不更改旧编号对应的内容。新请求先保存后发送，之后继续使用同一编号幂等重试；它不增加成功对话的计划轮数，也不影响已有 start 编号、已等待时长和服务器时间。

只核验、不创建平台数据：

```sh
python scripts/generate_translation_samples.py \
  --base-url http://127.0.0.1:8004 \
  --count 24 --seed 20261030 --pace-seconds 180 \
  --manifest /opt/lens_lab/translation-data/presentation-batch-20261030.json \
  --verify-only
```

## 样本与行为假设

24 条计划预先固定为 6 条基础、12 条中等、6 条较高能力组。每道客观题按带有个体与题目扰动的正确概率抽样，仅保留落入预定 `score_form()` 分组阈值的完整答卷，不直接伪填一个能力分。所有 18 道客观题与 6 道自评均作答；自评有独立噪声，不改变能力组。离散得分与相同客观答题模式可以重复。年级、年龄和实践经验按公开说明的本科生展示情景抽取，不宣称来自真实测试分布。

一般计划 2–3 轮，少数 4 轮。用户请求详略与补充背景的多少有差异；补充内容只从该会话参与者接口公开返回的场景卡片中选择。模型主动澄清时优先回应所问主题；最后明确要求按已知信息给出完整译文，未确认信息保留含混。脚本不向模型发送问卷分组、能力分、参考译文、评分量规或目标质量分。

提示版本为 `translation-dialogue-v2`。A组要求在关键背景尚未确认时先提出一个具体问题，明确无法补充后再给完整译文；S提示保持原样，不启用O优化模块。生成器同时核验实际首轮动作；默认场景的初始补充不足以确定全部关键语境，因此A应为澄清、S应为回答。未达到交互检查时保留真实结果并报错，不能把回答改标澄清。旧提示版本的记录保留其原回复与历史版本，不与本版本混算。

S/A 条件完全由后端按能力层平衡分配，脚本不提交条件。对没有既有失衡记录的 24 条批次，各能力层均为偶数，最终应为 12 条 S、12 条 A。若后端实际分配不满足此比例，核验会报错并保留原始结果，不修改分组来凑数。

## 完整性与边界

每条记录均经 `start → message（2–4次真实回复）→ draft → submit` HTTP 接口产生，生成器不连接数据库。最终提交内容逐字取自最后一条真实模型回复中明确分隔的完整译文，只去除分隔符和外围空白。若最后仍是澄清、格式不清、正文过短或缺少委托要求的人名，最多在 4 轮以内再请求完整译文；不能得到可提交全文时，保留失败记录，不用脚本自编译文替换。

完成后重新读取管理端记录，核验用途、答卷、本科背景、能力分、模型回复事件、2–4 轮对话、服务器 UTC 时间与最终译文一致性。此检查确认流程完整及译文来源，不能证明译文准确或高质量。

脚本不运行多模型评审、不制造分数、不使分布符合预期效应，也不把展示结果作为公平性结论。在本用途下，收集版本以不含评审团的材料描述计算，保留原空评审团版本兼容；原始完整材料快照仍保留。之后配置至少5个不同AI，即可对已提交的本版本译文发起首次评审，评分提示、原文和量规仍来自原记录快照。评审时另行冻结批次、实际模型和权重，配置变化不会混算不同批次均分，也不自动重评已完成记录。正式研究用途继续执行严格材料冻结和原配置评审，不使用该收集兼容规则。

私有 manifest 使用 `0600` 权限、临时文件原子替换，包含批次方法、固定计划、稳定请求编号、实际回复与完成核验。应保存在数据目录或其他私有位置，不能放在 `static/`，也不要提交至公开仓库。离线单元测试只验证计划、协议、等待和恢复逻辑；实际云 API 成功必须以运行日志及服务端回复事件为证。
