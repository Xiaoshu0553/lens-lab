# 翻译研究流程与评分口径

项目：《从“直接翻译”到“主动澄清”：面向翻译使用者的信息公平性研究与促进——基于生成式人工智能轻量化优化模块的设计与实证》——以中国矿业大学翻译用户为例。

本文说明平台支持的候选研究流程。软件实现与研究材料的测量效度、模型评审的有效性、干预效果是不同问题。平台保存实际观察结果，不按假设生成质量分或调节参与者表现。

## 参与者流程

1. 阅读并同意研究说明，确认中国矿业大学翻译使用者身份，填写成年年龄区间（含26岁及以上）、在读学段（专科、本科或研究生）与翻译经验。平台不要求姓名、学号和联系方式，身份确认属于自报。
2. 完成同一份翻译能力候选问卷。客观题覆盖翻译常识、语境理解和译文鉴赏，按固定答案计分；翻译经验和自我评价分开存储，不直接混入客观能力分。能力层阈值与材料版本一同固定，预测试后应审查信度、区分度及内容覆盖。
3. 系统在能力层内平衡分配实验条件。正式参与者不能选择条件；研究者试跑可以指定条件，试跑记录不纳入正式分析。
4. 所有人阅读同一翻译场景、英语段落与参与者补充资料，在相同对话轮数和时间限制内与模型交流。补充资料中包含影响译法的语境、人物或语气信息，参与者可自行决定是否和何时告知模型。
5. 在译文工作区编辑中文译文。草稿自动保存，刷新可恢复。完成至少一轮模型交流后提交最终译文，提交后内容冻结。
6. 研究者在后台发起统一多模型评分，查看评分依据、分歧与关键错误，再按预先确定的复核程序处理需要复核的记录。

## 当前两组与后续阶段

当前设计版本为 `translation-equity-baseline-v2`，处于公平性基线测试阶段，仅开放以下两组：

| 代码 | 条件 | 对话策略 |
| --- | --- | --- |
| S | 直接翻译 | 根据已有信息提供译文与说明，不主动索取补充背景；用户自行补充后可据此修订。 |
| A | 主动澄清 | 识别会改变译法的缺失信息，提出具体澄清问题，再据用户补充信息翻译。 |

两组共用英语原文、翻译任务、可供参与者阅读的补充资料与基础模型配置。模型不会因为参与者客观能力高低而获得不同的标准答案。

第一阶段先检验主动澄清对不同翻译能力群体的提升是否不同。“较高能力使用者收益更大”是待检验假设，不能当成必然结论，也不编码进分组、回答或评分。第二阶段应在取得并分析第一阶段实证结果后，再针对已识别的问题设计优化模块和新的验证实验；当前不开放 O 优化组，不预先确定优化策略。早期本地试跑的三组记录保留为历史版本，不能混入当前两组研究。

## 同一小说任务与信息缺口

候选任务使用自创英语小说段落，避免将小说知识记忆当成翻译能力。全部参与者可阅读相同的补充资料。模型的任务初始提示包含原文与共同翻译要求，影响译法的补充语境需要经由对话传递。参考译文和评审关键点仅供评分，不出现在翻译助手的任务提示中。

语境缺失可以导致称谓、代词指向、人物关系、双关、反讽或语体的多种译法。因此评分应结合固定场景与原文意义，不能只按参考译文逐字匹配。正式材料需避免唯一答案依赖未向任何参与者开放的秘密信息。

## 统一盲评与量化

后台为所有最终译文使用同一版量规和统一评审提示。每个不同 AI 模型都接收原文、完整共同背景、翻译要求、参考译文、量规和待评译文，独立对全部五个维度评分；不把语义、语境等维度分配成五种模型角色。评审不接收参与者能力层、实验条件、前测分数或对话过程，也不接收其他模型的评分。待评文本作为引用材料处理，不作为评审指令。

评审面板要求至少五个不同模型，最多九个。模型可以来自不同服务，也可以通过同一兼容网关调用不同模型。每个模型的名称、接口、权重、评分与验证状态都单独记录；重复的同一接口和模型不能靠不同标签冒充多个 AI。模型标识不同也不能证明其训练来源相互独立。

五个维度为语义准确、语境与人物一致、中文流畅、文体与声音、完整与克制，权重依次为35%、25%、15%、15%、10%。每个模型在每个维度给出0–100分、评分证据及严重错误记录。先按这些维度权重计算每个模型的总分，再按总分排序，去掉一个最高总分和一个最低总分。之后对剩余模型的预设权重重新归一化，计算加权平均；各维度汇总使用同一批保留模型和同一组归一化权重。总分相同时用模型编号稳定排序，剔除规则不读取实验条件。

默认各模型权重均为1，即保留模型等权；如果要使用不同权重，研究者应在正式收集前根据独立校准结果固定，不能根据当前译文的分数、参与者能力层或是否符合研究假设临时改权。全部原始评分、模型总分、原始和归一化权重、保留与剔除标记均保留。缺少任何一个配置模型的有效评分时，不对剩余评分临时计算综合分；后台显示失败并允许重试。

平台同时保留模型总分的标准差、极差和严重错误标记。去掉极值用于降低单个异常值的影响；多个不同模型综合评分是否减少偏差，需要通过实证验证，各模型的共同偏差不会必然相互抵消。严重错误不可因平均分较高而从记录中消失。正式使用前应安排独立人工译审校准，核对模型与人工在各维度上的一致性与系统偏差，并预先确定人工复核流程。未经实际完成的复核，平台不会声明“已人工确认”。

`demo` 模式只演示翻译和澄清交互，不运行研究评分。真实模型接口故障或评分结构无效会返回错误，不以随机构造的分数替代。提交译文与评审操作分开，避免评审失败导致参与者已提交的数据丢失。

## 后台统计与导出

后台按三种客观能力层和两个实验条件展示记录数、提交数、已评分数、质量均值、对话轮次和任务耗时。均值仅来自实际完成评分的相应记录；空样本显示缺失，不补零。

- 条件内高低能力差距：高能力层质量均值减低能力层质量均值。
- 能力层内澄清收益：A 条件质量均值减 S 条件质量均值。

以上“收益”是不同参与者条件之间的均值差，不是同一个人前后质量的提升。匿名会话编号不证明参与者去重，正式招募应控制重复参与。这些是描述性比较，不能单凭页面差值认定因果效应、统计显著性或等效。正式分析应预先指定样本量、主要终点、协变量、能力与条件交互项、缺失数据处理、评分校准以及等效界值，并同时考察高质量达成率、关键错误率和交互负担。后续优化阶段另行确定验证指标，不能将当前基线结果当成优化效果证据。

研究者试跑、`demo`、`pilot` 与 `live` 均有运行标记。后台分析不把旧校园任务记录或旧版 126 条合成样本当成翻译参与者。导出保留最终译文、问卷分数与答案、实验条件、材料和提示词版本、模型配置、对话、评分与记录类型，支持后续核查与重新分析。CSV 处理公式起始字符，减少将译文作为电子表格公式执行的风险。

运行信息分别记录翻译对话与多模型评审的后端类型、配置完整性和实际连通状态。`demo` 是规则模拟、评审关闭；`pilot`／`live` 使用模型 API。填写地址、密钥和模型名不能证明已经连通，应通过后台连通检查和真实试跑核验每个模型。调用成功只说明当时接口返回符合结构要求，不代表译文质量或评分效度已获得验证。

## 运行与冻结

默认本地数据库为 `translation-data/lens.sqlite3`。已有 `.env` 不会被自动覆盖，升级时应手动设置独立数据库路径；不同研究阶段建议使用独立数据库。新翻译记录使用独立的表，不将历史会话迁移成翻译样本。

| 模式 | 用途 | 限制 |
| --- | --- | --- |
| `demo` | 无密钥的本地功能演示 | 规则模拟；没有研究质量分。 |
| `pilot` | 真实模型预测试、审查问卷与场景 | 真实调用，保留预测试标记。 |
| `live` | 材料定稿后的正式收集 | 需要参与邀请码，并由研究者审查、确认冻结当前材料与配置。 |

对话及各评审模型的接口、模型名称、温度、输出上限、评审权重和材料版本都属于可比性条件。更换配置或材料后应重新审查并冻结，不应将其结果无标记地合并。后台冻结操作表示研究者确认了当前软件材料快照，不能替代研究伦理审批或实际专家审查。

远程模型会接收到对话内容和待评分译文，参与者不应输入真实个人隐私。参与者可通过退出删除本次翻译记录。

## 模型配置与凭据

翻译对话使用一个配置模型，S／A条件共用这个模型；评审单独配置至少五个不同模型，每个模型都完成全部五维评分。评审模型的权重与模型身份一起进入配置快照。后台允许保存尚不完整的配置草案，但评审面板未满足数量或身份要求时不生成综合分。

管理员可在后台填写接口地址、模型名称、API密钥和预设权重，再按对话模型、评审模型或全部模型执行实际连通检查。云端连接使用 Chat Completions 兼容接口，地址应填写 API 根路径，服务端统一追加 `/chat/completions`；本机标准端口的 Ollama 使用原生 `/api/chat` 调用。不同原生协议的服务应提供相应兼容入口，不能仅更换域名就当成已适配。连通失败的原因与成功验证时点分开显示，不能把已保存配置显示为已接通。修改配置即时影响新会话，历史会话和评分保留自己的配置快照。

私有配置默认保存在项目根目录 `.translation-models.json`，文件以受限权限原子写入，已从Git和Docker构建上下文排除。读取配置只返回是否配置密钥，不返回密钥内容。部署者应为私有配置提供独立持久化与受控备份；不得把包含密钥的文件放入公开仓库、研究数据导出或前端浏览器暂存。

## 入口与接口

默认网页为 `/`、`/admin`、`/admin/preview` 与 `/admin/instruments`，分别对应参与者、研究后台、研究者试跑及材料审查。管理员使用原有网页登录机制。历史校园任务入口为 `/legacy` 与 `/admin/legacy`。

新参与者接口前缀为 `/api/translation`，包括 `info`、`form`、`start`，以及 `session/{id}` 的恢复、`message`、`draft`、`submit` 和删除操作。新管理员接口前缀为 `/api/admin/translation`，包括 `summary`、`records`、逐记录查看与 `evaluate`、`materials`、`materials/freeze`、`export`，以及模型配置 `models`（GET／PUT）与连通检查 `models/check`（POST）。旧 `/api/start`、`/api/session`、`/api/admin` 的校园实验接口保留用于历史维护，不能用于当前翻译研究。
